# 产品目标

状态：规划基线。日期：2026-10-10。

## 用户体验

用户让 Codex 分析问题、生成报告或解释架构时，Agent 可以创建独立画布。用户在聊天旁查看结果，筛选数据、展开细节，再指定某个元素让 Agent 修改。画布可以保存、重开，并保留交互状态。

复现重点：一致的组件风格、持续可见的产物、诊断修复，以及用户反馈到源码修改的过程。

## MVP 范围

| 能力 | 预期行为 | 所属阶段 |
|---|---|---|
| 宿主接入 | 记录实际能力，确定可用展示与消息路径 | P0 |
| 生成与展示 | Skill 指导生成单文件 TSX，工具发布并打开产物 | P1 |
| 数据展示 | 统计、表格、基础图表、关系图和表单 | P1 |
| 更新与诊断 | Agent 获得文件、位置、错误信息和对应版本 | P1 |
| 状态恢复 | 画布重开后恢复明确声明的筛选和选择 | P1 |
| 元素反馈 | 选择元素并提交意见，Agent 定位源码修改 | P2 |
| 后续请求 | 明确按钮动作携带画布引用与选中上下文 | P2 |

## 首批场景

### 分析报告

一个画布同时呈现统计、表格和趋势。表格筛选可以改变图表，但不会自动触发 Agent 请求。刷新数据由明确操作发起。

### 架构说明

关系图与模块说明相互关联。点击节点可以展开细节，已实现文件打开能力时可以定位源码。当前视图可作为后续问题的上下文。

### 代码审查

Diff 与发现列表对应。用户选择一个发现并发起修改请求；请求带画布 ID、版本和相关源码位置。

## 交互原则

- 重要信息先呈现，视觉层级由 SDK 和生成规则共同约束。
- 数值带单位、时间范围和来源；缺失数据有明确标记。
- 筛选、折叠、缩放属于本地操作；请求 Agent 的动作有明确文案。
- 运行和编译错误可见，失败更新保留最近成功视图。
- 功能缺失时给出实际可用路径，避免可点击但无效果的按钮。
- 每个画布独立保存数据，会话界面实例各自绑定。

## 后续范围

历史版本、导出、分享、更多图表、可拖拽空间模式在核心流程完成后安排。首版先采用报告式 React 视图。

## 约束与未决项

- 当前 Codex 桌面宿主的原生 UI 和消息能力待 P0 观察。
- `cursor-canvas-web` 是渲染候选，组件覆盖和适配成本待 P1 确认。
- 本地开发以 Windows / PowerShell 为第一环境，接口保持可迁移。
- 依赖版本和项目公开许可证在相应阶段确定。
