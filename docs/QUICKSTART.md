# 1.0.0 使用指南

安装步骤见 [README](../README.md#安装到-codex)。运行需要 Node.js 22+；正式包的依赖由 `package-lock.json` 锁定。

## 打开文件

在 Codex 中让 Agent 调用 `canvas_open_file({ path, watch: true })`，或点击画布侧栏「打开文件」。选择文件导入，或填写绝对路径并开启自动更新。原生面板由宿主展示；宿主不支持时使用返回的预览地址。

命令行也可打开文件：

```sh
# 源码仓库中
pnpm canvas open examples/architecture.tsx
pnpm canvas open
# 已安装或解压的插件目录中
node dist/cli.mjs open /absolute/path/to/report.tsx
```

`open` 自动启动后台预览服务，相同路径复用已有画布，外部保存触发重新编译。源文件不会被画布编辑器回写；两边分别编辑时报告冲突。只有从项目 SDK 导入的单文件 TSX / JSX 受支持，详见 [SDK 契约](SDK.md)。

普通聊天文件链接由 Codex 决定打开方式，可能跳转外部编辑器。插件不能接管全部文件链接；预览请使用上述工具或入口。

## 交互与编辑

- 筛选、按钮等交互状态按画布保存。等待底部显示「已保存」后刷新，状态会恢复。
- 点击「源码」编辑并发布，源码版本递增；编译失败显示诊断，并保留最近成功画面。
- 开启 **Design mode** 后点击画布内容，选区面板显示元素与源码版本。「选父层」可扩大范围。
- 输入修改要求后，原生宿主支持时可「添加到聊天」或「发送修改请求」。浏览器模式使用「复制选区」，再粘贴到聊天。
- 只有明确发送操作会启动修改请求。普通交互、选择和文件刷新不会自动发消息。
- 侧栏删除按钮把画布移入「已删除」，可随时恢复；不会删除外部源文件。

选区定位使用 DOM 路径、稳定 part 标识和文本上下文，尚不是通用 AST 映射；界面展示行号时，仅代表源码中的唯一文本匹配。更多边界见 [发布记录](releases/1.0.0.md)。

## 启动与停止浏览器预览

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
# 端口被占用时，使用系统分配的端口
node dist/server.mjs --serve --port 0
```

打开日志返回的完整链接。URL 中的会话令牌用于首次绑定，加载后隐藏，刷新时从当前标签页恢复。链接和数据目录中的 ready 文件含本地凭据，不要公开。

前台服务按 Ctrl+C 停止，关闭浏览器标签页不会停止服务。通过 `open` 启动的后台服务记录在数据目录的 `preview-1.0.0.json`；停止前核对记录中的 PID 对应本插件的 `dist/server.mjs --serve`，不要结束其他 Node 进程。

外壳没有开发热重载。修改后重新构建并重启服务，再刷新或使用新链接。每个 MCP stdio 进程也会启动独立回环服务，随其退出。

## 数据与升级

正式可移植包把画布放在用户数据目录，具体路径见 [README](../README.md#数据与更新)。源码开发默认使用仓库 `.canvas-data/`。用 `CANVAS_DATA_DIR` 或 `--data-dir` 让多个入口访问同一数据根；升级前可复制整个数据目录备份。

`package:local` 为开发者本机保留原数据目录，写入机器路径，不可公开上传。正式打包和升级见 [发布指南](RELEASING.md)。源码版本使用乐观锁，旧编辑窗口必须刷新再提交；不会静默覆盖较新的修改。

主 MCP 服务固定名为 `codex-canvas`，保留早期兼容入口和资源地址。升级后当前聊天可能继续运行旧进程；重新加载插件或重启 Codex。旧卡片无法展示时，点击「重试」或调用 `canvas_open` 重新打开同一画布。

## 排查问题

1. **工具未出现：** 确认插件已启用，Node 在 Codex 的 PATH 中，重新加载插件。避免同时手动配置重复的 MCP 服务。
2. **原生面板无法显示：** 用 `canvas_probe` 检查宿主能力，临时使用返回的浏览器入口。不要降低生成 iframe 的 sandbox / CSP。
3. **选区不能直接发到聊天：** 功能依赖宿主声明的消息能力；浏览器模式可复制上下文。
4. **编译或运行报错：** 检查 SDK 导入和错误位置。编译成功不保证浏览器运行成功，错误或超时会显示提示。
5. **状态或源码冲突：** 先刷新读取最新版本，再重试修改。

提交问题前阅读 [贡献指南](../CONTRIBUTING.md)，移除日志中的令牌、私人路径和源文件内容。已执行的检查见 [1.0.0 验收记录](releases/1.0.0.md)，它与尚未观察的宿主行为分别记录。
