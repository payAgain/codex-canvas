# 0.4.1：旧卡片在升级后无法显示

日期：2026-10-10。

## 观察到的原因

桌面日志在 11:05 UTC 记录旧 `canvas_open` 卡片读取 `ui://codex-canvas/0.3.1/app.html` 失败，错误为 `unknown MCP server 'codex-canvas-v0-3-1'`。更早的无版本服务 `codex-canvas` 也出现相同错误。用户界面显示「未能显示 Codex Canvas」。

本机打包脚本曾把服务名随版本从 `codex-canvas` 改为 `codex-canvas-v0-3-1`，再改为 `codex-canvas-v0-4-0`。保存的卡片仍使用原服务名；只保留新服务无法恢复这些卡片。这个错误发生在 HTML 读取之前，与生成 TSX 或 iframe 布局无关。

同一聊天新调用 0.4.0 的 `canvas_open` 后，11:08 UTC 的宿主日志记录 `availableDisplayModes=[fullscreen]`、`displayMode=fullscreen` 和 `widget_running`。MCP Apps 侧边面板列表出现该 App；读取 DOM 得到标题「对照 · Cursor 生成稿」、Design mode 和「MCP App 已连接」，布局为 `panel`、版本 0.4.0，iframe 约 452 × 598 px。这是原生侧边面板实际出现的证据，不是浏览器预览的证据。

## 修复

- 本机安装包的主服务名固定为 `codex-canvas`，后续升级只改变 UI 资源的版本 URI。
- 保留两个已经发布的版本服务名，均指向新程序并使用 `--compat`。这些服务仅公开 App 可见工具，不注册重复 thread/file 入口，也不启动文件跟随定时器；主服务负责跟随文件。
- 当前 HTML 同时响应无版本、0.3.1 和 0.4.0 的历史资源 URI，使用当前面板元数据。
- 原生初始化保留工具结果里的明确画布 ID，通过当前 MCP 连接获取新会话，不使用旧结果的过期令牌。
- 运行中仅对明确的 `INVALID_SESSION` 错误重连并重试一次。该错误在操作执行前产生；网络超时及其他错误不自动重放写操作。重连保留当前画布绑定。
- 浏览器链接仍属于其原服务进程，不宣称重启后历史链接可继续使用。

## 状态

0.4.1 类型检查和应用构建通过，已由 Codex CLI 安装到本机插件缓存。安装后的 HTML/服务文件哈希与构建产物一致。新的 Codex app-server 通过插件加载器发现固定主服务（12 个工具）及两个兼容服务（各 8 个 App 工具）。

当前进行中的聊天仍使用 0.4.0 进程，重新打开的原生面板可用，但其 DOM 版本也仍为 0.4.0。因而本次不声称历史 0.3.1 卡片已恢复；它需要宿主加载新服务配置后点击「重试」。若保留旧连接，重启 Codex 可重新加载安装包。

未添加或运行测试套件；旧卡片点击「重试」后的实际恢复、Design mode 聊天请求、删除恢复等完整交互仍需单独观察。
