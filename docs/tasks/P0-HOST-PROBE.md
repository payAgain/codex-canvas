# P0：Codex 桌面宿主能力探测

状态：浏览器路线交付，原生兼容性待观察。日期：2026-10-10。

已实现 MCP 服务、UI 资源、thread 元数据、独立浏览器工作台和能力记录器。
0.2.0 已经由本机 Codex app-server 发现工具；原生 UI 展示仍未确认。0.1.0 的加载配置错误及修复见 [文件打开记录](P1-FILE-OPEN.md)。
实际结果及未知原因见 [接入观察](../compatibility/2026-10-10-local-preview.md)。
P1 已按浏览器路线推进到 [首个预览版](P1-FIRST-PREVIEW.md)。

## 目的

用最小 MCP 服务和 MCP App 判断这台机器上的 Codex 能否提供持续画布界面、主题、上下文和明确消息操作。
记录支持、缺失和未知情况，选择 P1 的实际接入路线。

下文保留原始任务规格；实现差异以当前路线图和接入观察为准。

## 计划交付物

- `packages/mcp-server`：最小服务与 UI resource 注册。
- `packages/host-bridge`：初始化与能力快照。
- `packages/renderer`：仅包含能力结果和明确操作按钮的探针页面。
- 本地插件清单与服务运行说明，所有引用指向真实入口。
- `.canvas-data/probes/`：本机标准化记录，Git 忽略。
- `docs/compatibility/`：去除私有内容后的宿主观察摘要。

P0 使用标准 MCP Apps 页面即可，组件兼容层在 P1 接入。

## 工具和界面

首个工具实现名为 `canvas_probe`，输入为空对象；宿主支持手动入口时也能打开。
工具返回服务端颁发的 `probeId` 和界面会话标识。
页面初始化后从真实宿主读取信息，不预设成功值。

页面分为：连接状态、宿主能力、主题样例、用户动作与原始结果。按钮只有在对应能力可用时启用；缺少能力时显示具体状态和复制路径。

## 观察矩阵

| 项目 | 观察方式 | 记录内容 |
|---|---|---|
| 工具 UI | 调用工具并读取 UI 资源 | 是否展示、显示位置、错误 |
| thread 入口 | 宿主提供入口时手动打开 | 是否可持续打开、界面实例 |
| 初始化 | MCP Apps connect / initialize | hostInfo、platform、hostCapabilities |
| 主题 | 初始化与宿主主题通知 | theme、styles、更新事件 |
| 标准工具调用 | UI 调用最小记录工具 | 请求来源、probeId、响应 |
| 模型上下文 | 用户点击添加探针摘要 | 接口是否存在、调用结果 |
| 消息草稿 | 用户点击写入明确探针文本 | 是否写入当前草稿、响应或错误 |
| 消息发送 | 用户明确点击发送按钮 | 是否进入当前会话、响应或错误 |
| 文件与资源 | 支持时读取或订阅指定资源 | 支持状态、更新到达情况 |
| 界面实例 | 在不同会话分别打开 | probeId 是否独立、是否串用 |

能力声明和实际可用性分开记录。接口存在但调用失败时保存失败证据，不能直接标为可用。
`send: false` 属于 OpenAI 扩展语义，缺失时不冒用标准接口实现草稿动作。

## 能力记录格式

拟定记录至少包含：

```json
{
  "probeId": "server-issued-id",
  "observedAt": "actual-observation-time",
  "host": {},
  "advertisedCapabilities": {},
  "features": {
    "threadEntrypoint": {
      "state": "unknown",
      "evidence": "not observed"
    }
  }
}
```

上面是示意格式，不是本机能力结果。
默认未知；初始化和实际观察后再填写支持或不支持。
持久化前删除认证信息、原始聊天内容和用户文件内容。

## 实施顺序

1. 从官方 SDK 当前已发布版本选择相容组合，固定版本并生成锁文件。
2. 实现最小 stdio MCP 服务、HTML UI 资源和打开工具。
3. 添加真实服务入口与本地插件清单，记录安装步骤。
4. 初始化 UI，显示真实能力，不预填任何成功状态。
5. 将主题、上下文和消息操作封装为可选适配器。
6. 观察宿主行为，保存原始结果和摘要。
7. 根据结果更新决策 0002 和 P1 接入任务。

用户明确操作的消息才发出。连接初始化、主题变更和普通按钮筛选均不提交聊天消息。

## 路线选择

- 原生 MCP App 和会话入口可用：采用宿主 UI 资源。
- 可展示工具 UI，但没有手动入口：保留工具打开与画布列表入口。
- UI 不可用：采用本地浏览器预览，继续通过 MCP 提供画布工具。
- 消息扩展不可用：提供画布引用和带版本的反馈复制。
- 能力尚未观察：保持未知，列出剩余观察项。

不同能力分别选择适配策略，不把一个失败推断为所有插件能力失败。
