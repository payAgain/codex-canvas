# 0.3：Cursor 风格与嵌入布局

日期：2026-10-10。状态：0.3.0 已实现、构建并安装；浏览器展示已观察，原生修复待新宿主实例验收。

## 比较结论

用户提供的 `cursor.tsx` 与 `notion-vs-obsidian.tsx` 均导入本项目 SDK，均已成功编译。主要差别来自提示词、构图和默认样式：

- Cursor 稿使用 24 px 标题、直接 Stat、一张主对比表、紧凑双栏摘要，信息先后清楚。
- 原 Skill 主要讲发布流程，缺少视觉约束；默认 Page 使用大标题、品牌眉题和绿色主题。生成稿有七个分节、多张表格和反复卡片包装，阅读负担较高。
- SDK 文档漏列已有的 trailing、weight、borderless、framed、rowTone 等参数，限制了模型对组件能力的使用。
- 原生成稿的官方来源和交互有价值；参考稿的主观评分没有方法说明，不应为模仿图表而照搬评分。

## 用户截图中的缺陷

截图显示 MCP 面板已在聊天内出现，状态为「MCP App 已连接」，但完整浏览器工作台（含侧栏）挤占了聊天区域，深色画布与浅色外壳不一致。

源码同时存在 `100vh` / `calc(100vh - ...)` 布局和 MCP Apps 自动尺寸通知。嵌入宿主按内容高度调整 viewport，而内容又依赖 viewport，可能形成高度反馈；不能从单张截图断定所有宿主表现。

还发现宿主任意 context 通知（包括尺寸变化）都会触发 `onTheme` 并重新挂载画布。现改为仅在主题值实际改变时重建 iframe，避免尺寸通知反复替换视图。

修复：在连接宿主前明确设置 embedded 布局；聊天内默认隐藏侧栏，通过按钮打开列表；预览区固定 520 px 并内部滚动，首页 420 px；所有嵌入布局取消 vh 高度；编辑面板相对当前卡片定位。浏览器保持独立工作台。生成代码仍在无同源权限的沙箱 iframe，未放宽权限。
