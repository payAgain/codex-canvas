# 1.1.1：画布列表、永久删除与 CI 修复

日期：2026-10-11。状态：实现、类型、构建、隔离数据回归与可移植包检查完成；本机已安装 1.1.1。当前聊天保留旧服务连接，新版原生 UI 待重新加载插件后观察。

## 需求

- 展开的画布列表提供直接关闭入口。
- 已删除画布支持永久删除。
- 查明 GitHub CI 失败原因并修复。

## 实现与边界

- 列表头部增加「关闭画布列表」按钮，Esc 关闭列表，焦点返回工具栏入口。
- 侧栏与「打开文件」的已删除分类都提供永久删除。确认对话框展示目标标题与删除范围，输入完整标题后才能提交；取消与 Esc 不发起删除。
- 服务端只处理已删除对象，写锁内校验 UUID、当前源码版本、删除时间和确认标题。移除该身份的当前库目录，包含源码历史、构建、交互状态和修改记录；清理同服务的所有关联会话与文件错误。
- 外部 TSX / JSX 源文件、其他画布、共享 workspace/主题偏好与旧迁移备份保留。当前库不能恢复该身份；文件跟随不会用旧身份重建画布。
- 用户请求开发功能不等于请求清空现有数据，本次没有永久删除用户画布。

## CI 原因与证据

- GitHub run `38138301712`（1.1.0 功能提交）：Ubuntu、Windows、macOS 都在 `pnpm check` 的 MCP 测试失败，日志仍要求 `data-version="1.0.0"`，实际页面已经是 1.1.0。修复为读取发布清单的实际版本，保留资源内容检查。
- 默认目录断言同步为固定 Codex 插件数据目录。存储位置作为可注入参数用于测试，迁移用临时 home/Codex 目录，避免检查触及真实用户库。
- 用户明确要求解决 CI，因而本轮运行项目检查：类型/构建通过，22 项测试全通过，发布清单、锁文件与文档链接检查通过。
- 新增隔离数据检查覆盖永久删除的确认、版本/删除状态冲突、恢复后旧确认拒绝、外部文件和其他画布保留、文件跟随、失效会话与多会话绑定清理；迁移保留身份、已删除历史和主题，排除旧服务凭据。
- 删除后的界面绑定会在永久删除成功或列表刷新时清除，避免后续会话续期寻找已移除身份；恢复旧卡片时仍可浏览其他画布。相应宿主桥回归通过。
- 可移植包从锁文件安装依赖、独立 stdio 启动与真实 TSX 编译通过（macOS arm64）；安装记录确认已启用 1.1.1，当前聊天工具仍返回 1.1.0，未以旧界面替代新版 UI 验收。
- 跨平台协议与安装包检查使用现有 [CI 工作流](../../.github/workflows/ci.yml)。自动化回归不等于各平台原生 UI 已观察。
