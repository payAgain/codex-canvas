# 主动使用 Canvas 回答

日期：2026-10-12。状态：技能、插件描述与 MCP 提示已实现；关闭旧服务后 CLI 本地重装成功，用户随后授权的 Windows 本机 CI 同等检查通过，实际隐式调用待重连后观察。当前发行仍为 1.1.1，本次改动尚未随发行包发布。

## 需求与实现

用户希望 AI 在画布能更直接解释答案时主动调用插件，不必每次点名。

- 技能发现描述覆盖架构、调用/依赖关系、状态变化、多方案比较和数据趋势；正文明确在可视化有实际收益时直接创建/打开，不只提出建议或要求用户确认。
- 显式设置 `policy.allow_implicit_invocation: true`。此前没有禁止隐式调用；本次同时改善发现描述和使用标准，而不是宣称打开了原本关闭的开关。
- 插件清单、MCP 初始化指令与发布工具描述同步表达主动使用的用途。简单回答、指定纯文字或其他格式/工具时遵循用户要求。
- 原生交付、SDK 限制、证据来源和修订身份规则保留。同一明确画布的后续问题优先更新已有对象。
- 主动调用只发生在用户已经发起的任务中；筛选、点选、文件更新不启动 Agent，也不代用户发送聊天消息。

## 证据与边界

- [OpenAI 技能文档](https://developers.openai.com/plugins/concepts/skills) 描述模型先读取名称和描述，再按任务匹配加载技能；这是文档接口，不是本次实际触发证据。
- 实现阶段 `pnpm build` 的类型检查与生产构建成功，本机专用包及锁定依赖安装完成，当时按项目要求没有运行测试。用户随后明确要求测试并在通过后推送，已运行现有检查，没有新增测试套件。
- Windows x64 / Node.js 22 本机 `pnpm install --frozen-lockfile` 与 `pnpm check` 通过：类型、构建、22 项隔离回归及发布清单/文档链接/候选文件检查。技能静态校验通过；校验器以 Python UTF-8 模式运行，避免 Windows 默认 GBK 读取中文失败。
- `pnpm package:release`、`node scripts/check-package.mjs` 与 `pnpm release:archive` 通过：从锁文件安装依赖，在临时库启动 stdio 服务并编译真实 TSX，生成含 136 个文件的 ZIP 并核对 SHA-256。仅为本机检查产物，不上传或覆盖已发布 v1.1.1 资产。
- marketplace 已切换到本次构建目录。首次 `codex plugin add` 在替换运行中的旧缓存目录时返回 Windows 拒绝访问；随后用户要求直接关闭服务、不备份。已停止该插件的主/兼容 Node 服务，删除本次创建的文件备份，再次 CLI 安装成功，返回版本 1.1.1 和安装缓存路径。
- 本地技能缓存包含主动使用描述与隐式调用策略，插件仍启用；原画布数据目录保留。安装结果不等同于新聊天中的实际触发证据。
- 隐式调用仍由宿主与模型选择，不能保证每次适用问题都触发。需重新加载插件或开始新聊天后观察，例如直接问「解释这个项目的架构」或「比较这三个方案的取舍」。
