# Canvas Examples

六个可运行的单文件画布，覆盖报告、结构说明、决策、计划、图表和审查。每个示例只从 `@codex-canvas/sdk` 导入；界面使用中文，可让 Codex 翻译或替换内容。

## 打开示例

在仓库根目录完成依赖安装与构建后运行：

```sh
pnpm canvas open examples/report.tsx
```

替换文件名即可体验其他示例。安装插件后，也可以把文件交给 Codex 并说“用 Codex Canvas 打开这个文件”，或使用工作台的「打开文件」。工作台首页提供报告、架构、审查三个快捷模板；另外三个通过文件入口打开。

## 选择一个起点

| 示例 | 展示与交互 | 可复用的设计 |
|---|---|---|
| [report.tsx](report.tsx) | 团队筛选、统计、折线图、明细表 | 一份筛选数据驱动整页报告 |
| [architecture.tsx](architecture.tsx) | SVG 模块关系图、点击或键盘选择节点、职责详情 | 图与文字联动；颜色跟随主题 |
| [comparison.tsx](comparison.tsx) | 按使用场景切换建议、定性对比表 | 先给选择依据，再展开差异 |
| [roadmap.tsx](roadmap.tsx) | 八周时间条、状态筛选、阶段详情 | CSS Grid 时间轴；范围与交付物分层 |
| [charts.tsx](charts.tsx) | 时间范围筛选、分组柱状图、环形图、派生统计 | 从同一数据集计算图表与总量 |
| [review.tsx](review.tsx) | 严重程度筛选、发现列表、建议伪代码 | 可选择的发现详情与稳定 part 标识 |

画面见 [README 画廊](../README.md#示例画廊)。筛选和选择通过 `useCanvasState` 保存在各自画布中，普通交互不发送 AI 消息。

## 试着让 Codex 改一改

| 从这个示例开始 | 可以直接使用的提示词 |
|---|---|
| 数据报告 | “保留这份报告的筛选结构，替换为我提供的数据。指标必须从数据计算，并标明单位与来源。” |
| 系统架构 | “参考这个可点击模块图，解释当前项目的调用关系。点击模块显示职责、输入输出和代码位置。” |
| 方案对比 | “把这两种方案按使用场景对比。先给建议与依据，不编造评分；无法确定的差异明确标注。” |
| 项目排期 | “把这些任务排成时间条，支持按状态筛选。只使用我提供的日期和负责人，缺失信息留空。” |
| 常用统计图 | “根据这个 CSV 生成柱状图与来源占比图，时间范围切换时同步更新总量和图表，标明统计口径。” |
| 代码审查 | “把这份真实审查结果按严重程度整理，点击一条发现展开证据和修改建议，不增添不存在的问题。” |

## 数据与复用边界

- 报告、统计图使用内置虚构数据；排期是虚构的八周计划，与项目路线图无关。
- 选型示例是简化的教学模型，不是供应商评测；审查发现及伪代码不代表本项目仍存在这些缺陷。
- 架构示例表达模块的逻辑关系，箭头不代表直接网络或文件访问权限。
- `pnpm demo` 是另一条入口：从当前仓库采集真实源码统计并生成报告，采集时间与来源会写入内容。
- 这些示例采用项目的 [MIT 许可证](../LICENSE)。组件与导入限制见 [SDK 契约](../docs/SDK.md)。
